# anon-pii v0.3.10

This patch brings Unicode column-header context to native downloads. The fix
is already available in the browser; native archives through v0.3.9 lack it.
No migration is required.

## What changed

A phone value aligned beneath `Éléments déjà vérifiés  phone` could remain
visible because header alignment compared UTF-8 byte offsets. Column context
now compares Unicode scalar positions in normalized detection text. Accents
and other multibyte characters in either the header or value prefix no longer
shift alignment merely because of their byte width.

Lowercase keyword spans map back to their original header columns, including
letters such as `İ` that expand when lowercased. Whole-string casing, custom
keyword spelling, first-occurrence matching, the 20-line lookback, four-scalar
tolerance, local keyword window, and score thresholds remain unchanged. The
phone rule still requires context and keeps its score of `0.6`.

Mapping format, CLI interfaces, dependencies, and release features are unchanged.
The release retains encoded-URL masking, grouped UK IBAN support, and the
standalone batch-restoration fix from previous releases.

## Verification and limits

Archive checks require complete phone masking in previews and actual child
input, followed by exact restored bytes. They compare aligned ASCII and accented
headers with wrong-column, missing-keyword, and threshold controls. Existing
support-ticket, encoded-URL, password, IBAN, wrapped-email, custom-regex, SQL
E-string, local API, and standalone restore checks remain gates. Transaction
checks require no persisted mapping; standalone restore uses its own temporary
explicit mapping. These are fictional or public maintainer vectors, not customer
adoption data.

Columns count scalars in normalized text, not screen width. Tabs count once;
remaining combining marks and wide characters may not align visually. This is
limited text alignment, not a table parser. Context-free phone values remain
outside this correction. Detection can miss sensitive values; review prepared
text before sharing it.

The unchanged fictional corpus records 45 TP, 0 FP, and 1 FN with default
features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.10/docs/quality.md).
These are regression measurements, not production-accuracy estimates.

## Downloads and installation

The release provides Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and macOS
Apple Silicon archives containing `anon-pii`, README, and MIT LICENSE, alongside
`SHA256SUMS` and SPDX/CycloneDX SBOMs. Download the archive and checksum file from
the same release, verify the checksum before extracting, and check
`./anon-pii --version` afterward.

Archives include `ner-lite,proxy,pdf`. Enable heuristic CLI name detection with
`--ner`; the local API is available with `./anon-pii api`. ML NER, OCR, and XLSX
are excluded. Windows and Linux aarch64 have no prebuilt archives. Source builds
require Rust 1.88 or newer; use `cargo install --locked --path . --features
ner-lite,proxy` for API support. The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.10/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features.
