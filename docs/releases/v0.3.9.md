# anon-pii v0.3.9

This patch brings complete masking of URLs with singly percent-encoded HTTP(S)
schemes to native downloads. The fix is already available in the browser;
native archives through v0.3.8 lack it. No migration is required.

## What changed

A ticket URL such as `https%3A%2F%2Fexample.invalid/?note=before%20after` could
leave `%20after` visible after a URL token. The built-in recognizer now masks
the complete URL while preserving its exact original spelling for restoration.
Each character of the lowercase `http://` or `https://` scheme may be literal
or once percent-encoded, including mixed forms such as `h%74tps:%2F/`.
Percent-encoded spaces, quotes, and newlines in the body stay inside the token;
literal surrounding boundaries retain their existing behavior.

The local API's `/analyze` results remain non-overlapping and feed `/anonymize`
directly, including when only an inner entity type is selected. Query audits
still split original query delimiters before decoding values; encoded query
punctuation does not create new raw query structure. Source offsets and exact
restoration remain correct after Unicode normalization and SQL/CSV decoding.
Thresholds, entity selection, custom recognizers, and enclosing-password
behavior are unchanged.

Mapping format, CLI interfaces, dependencies, and release features are unchanged.
The release retains grouped UK IBAN support and the standalone batch-restoration
fix from previous releases.

## Verification and limits

Archive checks require complete masking before preview and actual child-process
handoff, then exact restored bytes. They cover partially and fully encoded
HTTP(S) schemes with encoded body separators and literal surrounding boundaries.
Existing support-ticket, password, IBAN, wrapped-email, custom-regex, SQL E-string,
local API, and standalone restore checks remain gates. Transaction checks require
no persisted mapping; standalone restore uses its own temporary explicit mapping.
These are fictional or public maintainer vectors, not customer adoption data.

This fix does not recursively decode schemes, add other schemes, or add support
for uppercase HTTP(S) schemes. It preserves the existing raw URL body boundaries
and is not semantic URL validation. Detection can miss sensitive values; review
prepared text before sharing it.

The unchanged fictional corpus records 45 TP, 0 FP, and 1 FN with default
features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.9/docs/quality.md).
These are regression measurements, not production-accuracy estimates.

## Downloads and installation

The release provides Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and macOS
Apple Silicon archives containing `anon-pii`, README, and MIT LICENSE, alongside
`SHA256SUMS` and SPDX/CycloneDX SBOMs. Download the archive and checksum file from
the same release, verify the checksum before extracting, and check
`./anon-pii --version` afterward.

Archives include `ner-lite,proxy,pdf`. Enable heuristic CLI name detection with
`--ner`; the local API is available with `./anon-pii api`. ML NER, OCR, and XLSX
are excluded. Windows and Linux aarch64 have no prebuilt archives. Source builds
require Rust 1.88 or newer; use `cargo install --locked --path . --features
ner-lite,proxy` for API support. The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.9/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features.
