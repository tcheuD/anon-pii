# anon-pii v0.3.2

This patch brings lowercase and mixed-case IBAN detection to the native release
archives, preserving the original spelling when tokens are restored. It also
fixes heuristic name-detection fallback in source builds using optional ML NER
with the local API or proxy.

## What changed

- A ticket containing `IBAN gb82west12345698765432` now replaces the complete
  compact account with an `IBAN_CODE` token. Generic compact IBANs accept ASCII
  lowercase and mixed casing while retaining context, checksum, and confidence
  requirements.
- Fixed French compact and print forms also accept ASCII casing and retain
  their `FR_IBAN` classification. Preparation preserves surrounding prose;
  restoration recovers the exact original casing and bytes.
- Generic grouped lowercase IBANs remain unsupported. Broadly matching spaced
  lowercase words could consume text following an account number.
- API/proxy source builds with `ner` now retain heuristic `PERSON` detection
  when the ML model is unavailable or initialization returns an error or panics.
  Successfully initialized ML remains the sole name detector. The fallback was
  checked with deterministic initialization outcomes; this is not a claim of
  successful model inference or broader ONNX Runtime compatibility.
- Extracted-archive smoke checks cover the new IBAN spans in preview and actual
  child input, exact restoration, invalid checksums, and missing generic context.
  The existing custom-regex and support-ticket checks remain in place.

The browser engine already includes the IBAN fix. No dependencies, command
interfaces, or mapping formats change in this release. The unchanged fictional
quality corpus now requires the previously missed lowercase IBAN; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.2/docs/quality.md).
These are maintainer regression checks, not customer-adoption measurements.

## Downloads and installation

The release workflow builds Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and
macOS Apple Silicon archives, each containing `anon-pii`, README, and MIT
LICENSE. It publishes `SHA256SUMS` and SPDX/CycloneDX SBOMs with the archives.
Verify the archive checksum before extracting, then check `./anon-pii --version`.

Archives include `ner-lite,proxy,pdf`; enable heuristic names with `--ner`.
ML NER, OCR, and XLSX are excluded. The ML-initialization fallback change applies
to source builds with `ner`, not to an ML engine in the archives. Windows and
Linux aarch64 have no prebuilt archives. Source builds require Rust 1.88 or newer
and should retain the checked-in lockfile with
`cargo install --locked --path . --features ner-lite`. The crate is not published
on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.2/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features, rather
than only the code linked into each binary.

Detection can still miss sensitive values. Review prepared text before sharing
it. Existing privacy and behavior limits from
[v0.3.0](https://github.com/tcheuD/anon-pii/blob/v0.3.0/docs/releases/v0.3.0.md)
continue to apply.
