# anon-pii v0.3.7

This patch brings the batch-restoration fix to native downloads. Standalone
`anon-pii restore --mapping ...` no longer repeatedly scans the same suffix when
a reply contains many opening brackets before a closing bracket. Native archives
through v0.3.6 retain that slowdown.

## What changed

The batch scanner reuses the next closing-bracket position and skips exact
mapping lookups when a candidate is longer than every stored token. Known tokens
still restore to their original values; unknown placeholders and surrounding
malformed brackets stay intact, and repeated known tokens each count as a replacement.

This change applies to standalone bracketed restoration. `run` already uses a
separate streaming restorer for child stdout. Detection rules, mapping format,
dependencies, and CLI interfaces are unchanged. No migration is required.

The browser reply restorer already includes this improvement. Browser clipboard
and Undo fixes are deployed independently from the native archives.

## Verification and limits

Every extracted native archive must create an integrity-protected mapping for a
fictional email address, then restore a reply containing two million opening
brackets, two known tokens, an unknown placeholder, and Unicode text. The archive
check requires exact output bytes, exactly two reported replacements, and an
unchanged mapping file within the existing 30-second process timeout. This is a
bounded regression check, not a throughput benchmark or a complexity guarantee
for arbitrary imported mappings.

Existing preview, actual child-input, support-ticket, complete-password,
wrapped-email, custom-regex, IBAN, and API handoff checks remain release gates.
Transaction and API checks continue to require no persisted mapping; the
standalone restore check uses its own explicit temporary mapping.

The existing fictional maintainer baseline records 45 TP, 0 FP, and 1 FN with
default features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.7/docs/quality.md).
This restoration patch does not change detection rules. These are regression
measurements, not customer adoption or production-accuracy estimates. Detection
can miss sensitive values; review prepared text before sharing it.

## Downloads and installation

The release provides Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and macOS
Apple Silicon archives containing `anon-pii`, README, and MIT LICENSE, alongside
`SHA256SUMS` and SPDX/CycloneDX SBOMs. Download the archive and checksum file from
the same release, verify the checksum before extracting, and check
`./anon-pii --version` afterward.

Archives include `ner-lite,proxy,pdf`. Enable heuristic CLI name detection with
`--ner`; the local API is available with `./anon-pii api`. ML NER, OCR, and XLSX
are excluded. Windows and Linux aarch64 have no prebuilt archives. Source builds
require Rust 1.88 or newer; use `cargo install --locked --path . --features
ner-lite,proxy` for API support. The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.7/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features.
