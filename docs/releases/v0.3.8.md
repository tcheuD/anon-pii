# anon-pii v0.3.8

This patch brings complete encoded-URL masking and grouped UK IBAN casing support
to native downloads. Both improvements are already available in the browser;
native archives through v0.3.7 lack them. No migration is required.

## What changed

URLs containing percent-encoded spaces, quotes, or delimiters are masked as one
complete URL when the scheme is recognized before percent decoding. Previously,
a ticket URL such as `https://example.invalid/?note=before%20after` could leave
`%20after` visible. Query values are still decoded separately for inner PII audit
detections, which retain their original source spans. The local API's `/analyze`
results remain non-overlapping and can feed `/anonymize` directly, including
when only an inner entity type is selected. Exact restoration preserves the
original percent escapes, Unicode text, and surrounding punctuation.

Grouped UK IBANs now support lowercase and mixed ASCII casing, for example
`IBAN gb82 west 1234 5698 7654 32`. The fixed 4-4-4-4-4-2 groups accept spaces or
tabs, validate UK fields and the mod-97 checksum, and require a financial keyword
outside the matched value. The new rule cannot use a `BANK` or `BICA` bank
identifier as its own context. It keeps score `0.7`; threshold `0.8` rejects it.
Compact UK IBANs retain their existing context-free detection.

Mapping format, CLI interfaces, dependencies, and release feature selection are
unchanged. The release also retains v0.3.7's standalone batch-restoration fix.

## Verification and limits

Archive checks require complete tokenization before preview or child-process
handoff, exact restored bytes, and correct API source spans for encoded URL
values. They also cover grouped UK IBAN casing, separators, external context,
checksums, and unsupported controls. Existing support-ticket, complete-password,
wrapped-email, custom-regex, SQL E-string, and standalone restore checks remain
release gates. Transactions and API checks require no persisted mapping;
standalone restore uses its own explicit temporary mapping. These checks use
fictional or public test vectors; they do not measure customer adoption.

Fully percent-encoded URL schemes retain the existing decoded matching path and
its boundary limitations. The new lowercase/mixed-case grouped UK rule does not
cross line breaks. The broader generic uppercase IBAN matcher and custom URL
recognizers retain their existing behavior. Detection can miss sensitive values;
review prepared text before sharing it.

The unchanged fictional maintainer corpus records 45 TP, 0 FP, and 1 FN with
default features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.8/docs/quality.md).
These are regression measurements, not production-accuracy estimates.

## Downloads and installation

The release provides Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and macOS
Apple Silicon archives containing `anon-pii`, README, and MIT LICENSE, alongside
`SHA256SUMS` and SPDX/CycloneDX SBOMs. Download the archive and checksum file from
the same release, verify the checksum before extracting, and check
`./anon-pii --version` afterward.

Archives include `ner-lite,proxy,pdf`. Enable heuristic CLI name detection with
`--ner`; the local API is available with `./anon-pii api`. ML NER, OCR, and XLSX
are excluded. Windows and Linux aarch64 have no prebuilt archives. Source builds
require Rust 1.88 or newer; use `cargo install --locked --path . --features
ner-lite,proxy` for API support. The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.8/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features.
