# anon-pii v0.3.4

This patch packages complete password-assignment masking for the native release
archives and fixes entity selection in the local API. It also includes the
browser restoration feedback and guide-navigation improvements made since
v0.3.3.

## What changed

- A recognized assignment such as
  `password="prefix ada@example.invalid suffix"` is masked as a complete
  `PASSWORD` token. Previously, the nested email could replace the password
  detection and leave the surrounding parts of the password visible. Nested
  names, addresses, URLs, and credential fragments no longer remove an enclosing
  password detection merely because they are more specific types.
- A more specific classification is retained when it covers the entire assigned
  value and the original assignment syntax establishes that boundary. Encoded
  or ambiguous wrappers conservatively keep the complete assignment under one
  token. Spaces inside quoted passwords and punctuation such as `&` remain part
  of the value. Restoration retains the exact original source spelling.
- The local API applies `/analyze`'s requested `entities` before overlap
  resolution. Selecting `EMAIL_ADDRESS` can therefore return the email inside
  a password assignment; selecting `PASSWORD` retains the assignment even when
  an excluded detector recognizes its full value. Omitting `entities` keeps the
  default complete-password behavior. Empty selections or selections containing
  only unknown types return no detections, and URL-inner audit results respect
  the selection. For the nested-email example, the selected email span can be
  passed to `/anonymize` to mask that email.
- The browser reports how many token occurrences were restored, including
  repeats, and flags unrecognized placeholders with the usual token shape.
  Copy feedback retains that outcome. Changed or incomplete tokens may not
  match the notice, so replies still need review.
- The browser's support-ticket guide opens in a separate tab, preserving the
  prepared ticket and mapping while the user reads it. Explicitly leaving or
  reloading the workspace still clears its session.

The browser engine includes the password fix. Native archives from v0.3.3 and
earlier predate it. No dependencies, CLI command interfaces, or mapping formats
change in this patch. The browser remains local and account-free, without
saving ticket text or mappings to browser storage.

## Verification and limits

Release smoke checks require complete password-overlap and normalized-wrapper
spans in both preview output and actual child input, exact restored output,
absence of persisted transaction mappings, and controls preserving more specific
classifications for complete values. Existing support-ticket, custom-regex,
IBAN, wrapped-email, and SQL checks remain release gates. API regressions cover
entity selection before overlap and the selected analyze-to-anonymize workflow.

The unchanged maintainer-owned fictional corpus baseline remains 44 TP, 0 FP,
and 2 FN with default features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.4/docs/quality.md).
These are regression measurements, not customer-adoption measurements or
production-accuracy guarantees. The deliberate context-free phone and IBAN
exceptions remain. Detection can still miss sensitive values; review prepared
text before sharing it.

## Downloads and installation

The release workflow builds Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and
macOS Apple Silicon archives, each containing `anon-pii`, README, and MIT
LICENSE. It publishes `SHA256SUMS` and SPDX/CycloneDX SBOMs with the archives.
Verify the archive checksum before extracting, then check `./anon-pii --version`.

Archives include `ner-lite,proxy,pdf`; enable heuristic names with `--ner`.
ML NER, OCR, and XLSX are excluded. Windows and Linux aarch64 have no prebuilt
archives. Source builds require Rust 1.88 or newer and should retain the
checked-in lockfile with `cargo install --locked --path . --features ner-lite`.
The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.4/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features, rather
than only the code linked into each binary. Existing privacy and behavior limits
from [v0.3.0](https://github.com/tcheuD/anon-pii/blob/v0.3.0/docs/releases/v0.3.0.md)
continue to apply, including review of missed values, session-local browser
mappings, and the CLI child's normal filesystem and network access.
