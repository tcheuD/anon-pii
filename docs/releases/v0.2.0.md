# anon-pii v0.2.0

This release makes the local AI-debugging roundtrip the core workflow: inspect
what recognized values become, pass tokens to a command, and restore known
tokens in its answer. It requires no account or AI service to try.

```bash
printf 'Contact john@example.com\n' | anon-pii run --dry-run
printf 'Contact john@example.com\n' | anon-pii run -- cat
```

## What changed since v0.1.1

- `anon-pii run -- <command> [args...]` prepares finite UTF-8 stdin before
  starting the child, sends recognized values as reversible tokens, restores
  known bracketed tokens in child stdout, and retains the mapping only in
  memory for that invocation. It preserves the child's exit status and streams
  stdout restoration across token boundaries.
- `run --dry-run` previews prepared stdin without executing a command or saving
  a mapping. Its stderr summary reports unique entity counts without original
  values. A command is optional for preview.
- Reversible mappings now fail safely when an operation cannot retain the
  entries required for restoration. Existing mappings are protected against
  accidental empty-map replacement. Unknown and malformed tokens remain
  unchanged during strict restoration.
- Detection preserves source spans through Unicode normalization, escaped
  text, URL encoding, and multiline paths. JSON keys remain intact, CSV record
  structure is preserved, and SQL transformations retain lexical structure.
- French IBAN detection validates the country-specific structure and checksum.
  Basic authentication recognizes validated Base64 credentials with a decoded
  `username:password` structure, replacing the credential while retaining the
  `Basic` scheme.
- A versioned synthetic quality contract now gates releases. On the unchanged
  62-case `debug-pii-v1` corpus, default features at threshold `0.5` report
  **42 true positives, 0 false positives, and 4 false negatives** across 46
  annotated spans. Basic-auth coverage improved the previous 41/0/5 result.
  This is a project-owned test corpus, not a production accuracy estimate.
- Release tags must match the package version and identify a commit contained
  in main. Portable checks, crate packaging, and Rust 1.88 checks run before
  builds. Extracted archives undergo a preview and roundtrip smoke test on
  each target platform, and downloads include `SHA256SUMS`.
- The lockfile updates `rustls` to 0.23.45 to address RUSTSEC-2026-0285 and
  `rustls-webpki` to 0.103.15. It also replaces the yanked `chacha20` release
  with 0.10.2. No advisory ignore was added for these updates.

The corpus hash, measured source revision, exact command, exclusions, and
integer results are recorded in
[the quality policy](https://github.com/tcheuD/anon-pii/blob/v0.2.0/docs/quality.md).

## Downloads and installation

| Archive | Tested build and smoke-test environment |
|---------|----------------------------------------|
| `anon-pii-linux-x86_64.tar.gz` | Ubuntu 24.04, GNU libc, x86_64 |
| `anon-pii-macos-x86_64.tar.gz` | macOS 15, Intel |
| `anon-pii-macos-aarch64.tar.gz` | macOS 15, Apple Silicon |

Download your archive and `SHA256SUMS` from this release, verify the checksum,
and extract the archive. It contains `anon-pii`, README, and LICENSE. Run
`./anon-pii --version` before installing the binary in a directory on your PATH.
These archives include `ner-lite,proxy,pdf`; use `--ner` to enable heuristic
name detection. The API, UI, and proxy remain secondary local modes, and PDF
redaction remains experimental.

There are no Windows or Linux aarch64 prebuilt archives. The crate is not yet
published on crates.io. Source installation uses Rust 1.88 or newer:

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/tcheuD/anon-pii.git
cd anon-pii
cargo install --locked --path .
```

Source builds can opt into features separately. ML NER (`ner`) requires ONNX
Runtime and downloaded models; OCR (`image`) requires Tesseract and language
data. Neither is compiled into the archives. XLSX is a detection scaffold, not
workbook anonymization, and is also excluded from the archives. SPDX and
CycloneDX SBOMs describe the Cargo dependency graph including optional features.

## Behavior and migration notes

Existing standalone anonymize/restore flows remain available. Use `run` when
you want a single invocation to own the mapping; use the detached flow when
you intentionally need a persistent mapping and later restoration. Persisted
mapping files contain original values in plaintext and must be protected.

`run` accepts finite UTF-8 stdin and buffers it before launch, with a 50 MB
default limit. It is not an interactive terminal or unbounded log stream.
Child stderr passes through unchanged. The child retains normal filesystem,
environment, network, and subprocess access; this wrapper is not a sandbox.

Preview does not prove that a payload is anonymous. Review it for missed
values. Tokens belong to that invocation; a later `run` creates fresh tokens,
and preview output cannot be restored after its in-memory mapping is gone.
The four reviewed corpus misses are context-free phone, context-free IBAN,
lowercase IBAN, and newline-split email. Malformed or newline-split Basic
credentials are not covered. New sensitive values generated by the child are
not automatically removed from its output.

Dependency advisory status and accepted informational warnings are documented
in [the dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.2.0/docs/dependency-policy.md).
No compliance certification or comprehensive detection guarantee is claimed.
