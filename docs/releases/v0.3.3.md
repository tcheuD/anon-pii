# anon-pii v0.3.3

This patch brings wrapped-email detection and PostgreSQL E-string control-escape
handling to the native release archives. Token preparation masks recognized
values before handing them to a child command, and restoration preserves their
exact original spelling.

## What changed

- An email split by one LF or CRLF immediately after `@`, with optional spaces
  or tabs before a complete domain, now becomes one email token. Surrounding
  prose, indentation, and original line endings survive the roundtrip.
- Blank lines, whitespace before the line break, and domains split across more
  lines remain unsupported. Rejected partial addresses cannot consume a complete
  address on the next line. A domain-only next line can be ambiguous; review the
  prepared text before sharing it.
- With `--format sql`, default token preparation decodes named controls
  (`\b`, `\f`, `\n`, `\r`, `\t`) inside PostgreSQL `E'...'` strings for detection.
  For example, `E'ada@\r\n\texample.com'` now masks the complete wrapped email,
  while restoration retains the literal backslash escape spelling.
- Ordinary and dollar-quoted SQL strings retain literal backslashes. Doubled
  backslashes in E-strings are not recursively decoded into named controls.
  This is not a full SQL escape parser; other replacement operators are unchanged.
- Extracted-archive smoke checks inspect complete wrapped-email and SQL spans
  in both preview and actual child input, exact restored output, negative
  controls, and absence of a persisted transaction mapping.

The browser already includes wrapped-email detection and continues to process
plain ticket text. Use the CLI's SQL format for SQL excerpts. No dependencies,
command interfaces, browser engine, or mapping formats change in this release.
The unchanged fictional quality corpus reports 44 TP, 0 FP, and 2 FN; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.3/docs/quality.md).
These are maintainer regression checks, not customer-adoption measurements.

## Downloads and installation

The release workflow builds Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and
macOS Apple Silicon archives, each containing `anon-pii`, README, and MIT
LICENSE. It publishes `SHA256SUMS` and SPDX/CycloneDX SBOMs with the archives.
Verify the archive checksum before extracting, then check `./anon-pii --version`.

Archives include `ner-lite,proxy,pdf`; enable heuristic names with `--ner`.
ML NER, OCR, and XLSX are excluded. Windows and Linux aarch64 have no prebuilt
archives. Source builds require Rust 1.88 or newer and should retain the
checked-in lockfile with `cargo install --locked --path . --features ner-lite`.
The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.3/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features, rather
than only the code linked into each binary.

Detection can still miss sensitive values. Review prepared text before sharing
it. Existing privacy and behavior limits from
[v0.3.0](https://github.com/tcheuD/anon-pii/blob/v0.3.0/docs/releases/v0.3.0.md)
continue to apply.
