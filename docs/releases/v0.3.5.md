# anon-pii v0.3.5

This patch makes local API analysis results ready to send directly to the
anonymization endpoint, including URLs containing email addresses or phone
numbers. Native archives through v0.3.4 predate this fix.

## What changed

Previously, `/analyze` could return both an enclosing URL and overlapping
query-value audit detections. Forwarding that response to `/anonymize` returned
HTTP 422. The API now returns nonoverlapping spans in source order, preserving
the enclosing URL when it is selected.

Entity selection still happens before overlap resolution. Selecting only
`EMAIL_ADDRESS` or `FR_PHONE_NUMBER` can therefore mask the corresponding value
inside a URL while preserving the surrounding text. Offsets remain UTF-8 byte
positions in the original input, including percent-encoded source spelling.
CLI detection reports retain the nested audit details, and `/anonymize` still
rejects overlapping spans supplied by a caller.

The [API guide](https://github.com/tcheuD/anon-pii/blob/v0.3.5/docs/api.md) documents
this handoff and installation from source. No dependencies, browser engine,
mapping formats, or CLI command interfaces change. The browser remains local
and account-free without saving ticket text or mappings to browser storage.

## Verification and limits

Every extracted native archive must pass an actual local API handoff check for
encoded email and phone values, Unicode byte positions, separate entities after
a URL, and default, combined, and single-type selections. The check also requires
HTTP 422 for overlapping caller input and no persisted API mapping. Existing
preview, actual child input, exact restoration, complete-password, and other
native workflow checks remain release gates.

The unchanged fictional maintainer corpus remains 44 TP, 0 FP, and 2 FN with
default features, threshold `0.5`, and no NER; see the
[versioned measurements](https://github.com/tcheuD/anon-pii/blob/v0.3.5/docs/quality.md).
These are regression measurements, not customer adoption or production accuracy
estimates. Detection can miss sensitive values; review prepared text before
sharing it.

## Downloads and installation

The release provides Linux x86_64 (Ubuntu 24.04/glibc), macOS Intel, and macOS
Apple Silicon archives containing `anon-pii`, README, and MIT LICENSE, alongside
`SHA256SUMS` and SPDX/CycloneDX SBOMs. Verify the archive checksum before extracting
and check `./anon-pii --version` afterward.

Archives include `ner-lite,proxy,pdf`; the local API is available with
`./anon-pii api`. Enable heuristic CLI name detection with `--ner`. ML NER, OCR,
and XLSX are excluded from these archives. Windows and Linux aarch64 have no
prebuilt archives. Source builds require Rust 1.88 or newer; retain the lockfile
with `cargo install --locked --path . --features ner-lite,proxy` for API support.
The crate is not published on crates.io.

Dependency advisory checks remain release gates under the
[dependency policy](https://github.com/tcheuD/anon-pii/blob/v0.3.5/docs/dependency-policy.md).
SBOMs describe the Cargo dependency graph, including optional features.
