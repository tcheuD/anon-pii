Ticket text is processed in this page. The Rust engine runs locally through WebAssembly; this workspace does not send your text to an AI service or save it in browser storage. Heuristic name detection is enabled and can miss names or mark ordinary words. Always review the prepared text.

The mapping belongs to one prepared ticket and stays in this page's memory. Clear session, leaving, or reloading the page clears the workspace. Copies already on your clipboard or in another app are outside this session. Read the support-ticket guide ↗

The case
Four points

Keep the ticket reversible.

Prepare a ticket in your browser or use the CLI in your debugging workflow. Keep the original references available for the reply.

01

One ticket, one mapping

The browser workspace holds one prepared ticket's mapping in memory. anon-pii run does the same for one child process, restoring known tokens from stdout.

02

Browser or native CLI

Start in your browser with no account or AI key. For terminal workflows, the default CLI needs no Python environment, Docker container, long-running service, or ML runtime.

03

Validation where formats allow it

Checksum-backed identifiers use validators such as Luhn and IBAN mod-97; ambiguous patterns use context. Neither removes false positives or false negatives.

04

A versioned quality contract

Synthetic positive, negative, normalization and structured-format cases run in CI. Claims stay tied to a corpus and revision instead of a blanket accuracy ranking.

Install. Preview. Roundtrip.

Choose your platform below. The first roundtrip runs locally with cat; no AI tool or API key needed.

Download SHA256SUMS and compare your archive's SHA-256 digest with its matching entry before extracting. Use sha256sum on Linux or shasum -a 256 on macOS.

Linux x86_64 (glibc) · Download archive ↗
tar -xzf anon-pii-linux-x86_64.tar.gz
macOS Apple Silicon · Download archive ↗
tar -xzf anon-pii-macos-aarch64.tar.gz
macOS Intel · Download archive ↗
tar -xzf anon-pii-macos-x86_64.tar.gz
Install the extracted binary for your user
mkdir -p "$HOME/.local/bin"
install -m 755 anon-pii "$HOME/.local/bin/anon-pii"
export PATH="$HOME/.local/bin:$PATH"
anon-pii --version

Keep the PATH line in your shell profile. Release binaries include ner-lite,proxy,pdf; name detection requires --ner. ML NER, image OCR, and XLSX are excluded. The core workflow below needs no optional modes.

Or build the default core from source · Rust 1.88+
git clone https://github.com/tcheuD/anon-pii
cd anon-pii
cargo install --locked --path .

Source builds use no optional features by default and install to ~/.cargo/bin; keep that directory on your PATH.

1 · Preview locally — inspect for missed sensitive values
echo 'Error for john@example.com from 192.0.2.5' \
  | anon-pii run --dry-run
2 · Prove the roundtrip — cat receives tokens, you see originals
echo 'Error for john@example.com from 192.0.2.5' \
  | anon-pii run -- cat
# Error for john@example.com from 192.0.2.5
3 · Use your configured AI tool, for example Claude Code
echo 'Error for john@example.com from 192.0.2.5' \
  | anon-pii run -- claude -p "what failed?"

Each invocation creates fresh tokens and keeps its mapping in memory. Detection can miss values. The child still has normal filesystem and network access; see the run contract and limitations.
